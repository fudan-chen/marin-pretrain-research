读完这些故障后，自己的预训练应该怎样改

这份研究的中心结论是：预训练配方与实现细节必须一起评审。配比决定计划接触什么数据；缓存、取整、恢复和loss权重决定实际学习什么；优化器状态与路由决定同一批数据怎样更新模型；评估和checkpoint决定我们能否正确判断进展、可靠地继续训练。只盯其中一个loss曲线，无法覆盖这几条链。

数值诊断还须先核对目标合同：标签边界控制表明，非法目标可以给出有限 loss 与不一致的自动微分；分母与归约轴控制则表明，局部有限并不保证全局有限。正常入口可能已有保护，是否适用必须绑定实际执行路径，不能把人工反例当成 Hero 事故。

检查也要找到真正执行的保护：原 custom VJP 控制中，参考函数直接求导的异常没有在原 slow/scan 显式反向复现。后端评审应绑定注册链、残余与 cotangent，既不漏掉数值边界，也不把另一条路径的异常归因给实际训练。

更新量还受分块与转换位置影响：原 CE 梯度 dtype 控制在普通 BF16 输入中复现旧跨块累计少算、新 scan 保留总量；纯 FP16 的另一控制则定位 GEMM 前归零。按实际操作数、累计 buffer 和块大小判断，不能用 FP32 loss 或有限梯度替代更新验收。

配比实验的最新综合入口是六类干预对照：加权重、换子集、调顺序和改IO窗口，可能改变不同的实际输入。先声明希望测量的效应，再决定哪些身份、预算和状态必须固定。

配置校验也需核对执行方式：原混合器的断言控制表明，Python优化模式移除整块约束后，非法阶段可以产生合法范围内的重复身份。源码有检查、数据可读、实际曝光正确，是三个需要分别确认的条件。历史Hero是否使用该模式尚未知。

桶级配比还需检查归一化前后支持和整数曝光：数值合同控制表明，坏后续阶段可以被余数逻辑分成完整合法batch。预算守恒不能代替每桶实际配额核对。

保存验收的新增结论是：异步manager控制将完成future、源数组引用与一次性错误消费分开。第二次wait正常返回不能覆盖第一次失败；future列表保留也不能单独推断模型快照或RSS。

调用方的保存失败控制进一步说明：交接step/time可以在后台失败前推进，显式请求也可能已消费；需要单独的失败attempt与重试政策。metadata后的retention错误应先查清理，不能只按一次wait的成败决定全量重写。

下面把已有研究收束为可执行的判断。作者记录、固定源码、本地人工反例和建议实验分别标明。本章没有新增训练结果，不把本地检查通过当作535B稳定性证明。完整问题—动作—原因对照仍在15案工程总图和主报告；需要精确原值时沿链接进入专题。

先按症状进入，不必顺着版本号读

先分清哪一层改变了：输入与评分口径 → 路由和梯度 → 状态接续 → 实际运行环境。下面七个入口把源码机制、已有控制、下一项实验与结论边界对应起来。点击症状展开；它们帮助选择调查路径，不会自动判定根因。CPU反例、真实本地IO和生产训练证据不能互相替代。

换配比后，训练 loss 立刻下降

先查什么：先确认目标口径与输入，而不是先给配比排优劣。

源码说明：原next_token_loss与输出z-loss路径说明：预测不变，输入分布或有效目标质量改变也会改变日志；共同logit平移还可只改变输出z-loss。

最小对照：在两个checkpoint上分别评分同一份旧输入与新输入，保留四格N/T；纯CE和含z-loss目标分开。真实样本与分母不一致时，先修对齐。

怎样决定下一步：四格齐全，只能分解评分差异；要判断训练收益，还需冻结评估和独立续训确认。缺格时保留未知。

2. 想调整数据，先过三道检查

第一道：计划量与实际量有没有对上

库存约23.106T，训练目标18T，不能把库存占比直接当训练权重。40个语义cluster×5档形成200个训练桶，配置的另外23个组件属于验证来源。Q档也不是一套可直接迁移到任意数据的“质量真值”；评分窗口、校准和筛选实现需单独核对。数据配比、质量桶

对每桶同时存四项：库存量、阶段声明比例、整块整数计数、真实读取/评分量。阶段预算必须用历史batch累积换算；不足完整块的边缘单列，不能删掉后再宣称同预算。累计曝光轮数是预算量/库存量，不意味着每篇文档恰好出现相同次数。

检查不通过时先改读取与预算设计，不进入配比优劣排名。 否则在比较的可能是不同曝光量或不同文本，而不是自己想研究的比例。

第二道：验证变化是广泛改善还是集中在少数域

10月6日归档观察约9.75T/4K，当时仍在同一声明配比阶段；它是历史窗口，不是当前实时进度。197999→209999的宏CE改善约−0.0265，去PTB后其余15域平均约−0.00969；两个数字同时成立。twitterAAE的端点变差但中间有升有降，不能称作持续退化，更不能把它直接映射到某个训练cluster。原值与图

这里对自己的实验最实用的做法是：在选候选前确定目标域与保底域，记录平均值由谁推动；发现集中变化时，先核对该域真实输入、分母及可重复性。只看最好的域会漏掉退步，只看最差的一点也可能被波动误导。

需要重评时，记录检查器能区分模型视图、输入/分批/分母声明和逐批N差异。它不能替你生成真实运行记录，或独立验证记录内的数组哈希。

第三道：让一个实验只回答一个问题

现有候选中，197c与996f同时改变195个桶，40个域累计份额都变；这种比较不能单独证明“数学加量”或“高质量后置”有效。预算分解

精心调整配比不是从这组数字直接抄一个最优比例，而是：固定总预算，选一个接收域和明确供体，先判断到底研究域总量还是域内Q档；需要研究顺序时，先匹配每桶累计量与边缘块，再改变时序。候选选择用过的任务/seed不能独立证明选择后的收益，还需要冻结后的确认。

4. 一套最小而完整的配比实验

这里没有新的推荐百分比。缺少自己的库存、目标任务、历史曝光和预算时，给出百分比会掩盖这些决定性的输入。可以先按既有四臂草案做以下实验设计：

  1. 固定比较对象。 从同checkpoint与完整optimizer/router状态开始；保留旧配比强基线。冻结评估内容、模型视图、总token和墙钟预算口径。
  2. 明确交换。 声明接收域、供体、交换量，以及是否改变域内Q档。用整数混合块编译；记录零计数和集中余数。
  3. 把因素拆开。 旧总量/新总量与旧Q构成/新Q构成组成四臂。每臂预算、长度、batch历史和恢复前缀对齐；保留各自checkpoint和数据记录。
  4. 先确认收益，再研究顺序。 用冻结后的重复与保底任务检验方向；如果研究先后，匹配累计桶量并用共同边缘块控制余数，不在换顺序时悄悄换总量。
  5. 最后放大。 同时检查任务收益与工程稳定性。设置阶段结论为继续观察、退回设计或进入下一规模；只有代理BPB改善时，仍保留能力与迁移未知。

完整的阶段输入、产物和返回分支见七阶段管线。上面的顺序是对已有管线的阅读压缩，不改动18条规则的版本，也不新增一个“所有风险总分”。

拆批也可能改变目标：先核对分母

梯度累积审计追踪固定版通用Trainer、累积器与Hero专用路径。若各块返回有效token均值，普通平均会给不同有效数的块相同份额；人工标量例子甚至改变梯度方向。等固定位置分母和等有效分母都有一致的正例。当前Hero专用函数没有调用该通用累积器，因此这是一条迁移验收规则，不能归因其历史loss。真实模型还需验证路由、RNG、裁剪及optimizer状态。

前向有限仍需检查反向与触发条件

零权重审计已经在真实JAX CPU上复现：原mean全零weight时loss为0、反向为NaN；安全分母对照解决局部除零，但不能排除上游NaN。另一个有限输入padding正例与reference梯度一致。公开text配方在固定代码正常执行条件下应有46,126,080有效目标，因此这项局部复现不能解释Hero历史事故，需先取得实际T与inactive非有限值记录。

V50：空目标处理不能只把梯度或update改成0

原AdamH模块CPU对照确认：有历史moment时，零梯度仍产生非零更新；只丢弃最终update，状态仍推进，下一有效步也会改变。空目标应按实际global T与接受策略判断，不能按grad==0跳步，也不能用某个未使用expert的叶梯度为0触发整步跳过。moment/count、训练step、调度、EMA与QB应分别记录接受条件。本轮只执行optimizer局部对照，完整Hero步与事故触发仍未验证；规则锚点不变。

V51：裁剪验收要看归约范围和后续状态

分组章节的CPU对照确认三组各裁剪到1时合并范数为√3，且原AdamH首步近乎相同的参数更新可留下不同moment；固定后续参数与梯度，差异仍进入下一次update。验收需记录clip范围、系数/触发率、moment/count和后续有效步，不能只看首次更新相似。最新归档max_grad_norm=None；这不是Hero已启用裁剪的事件证据，规则锚点不变。

V52：加载器恢复控制

恢复时区分store预取水位、交付水位与完成更新水位。原异步host函数的人工控制表明，提前取到的索引不能代替state.step重建的下一批；相同索引仍须绑定token身份。加载器恢复控制。

V53：混合数据身份

同key与按名称计的配额仍不能重建序列：原混合类把有序dataset_index编码进ID，整数余数并列也受此顺序影响；有限库存长度与内容版本继续决定子索引身份。真实CPU映射控制。

V54：桶内shuffle与切分

固定seed的train/val切分仍依赖库存快照。原CPU控制在同快照下互斥，跨长度快照则出现旧train/new-val身份交集；最新Hero未声明启用该拆分，不据此认定泄漏。桶内shuffle与切分。

V55：小实验库存缩放

同比缩训练预算与库存，只在连续条件下保持曝光轮数。原train_sets逐桶floor后，小库存误差可能很大或变0；模型配比收益还需区分权重、库存多样性与重复曝光。原小实验控制。

V56：新MoE提案

新MoE提案把未写内存、路由梯度近似与调度预算同时带入评审。#9832/#9833快照均未合并；原patch语句CPU控制显示zero权重/float16小乘积的梯度边界。作者短窗提速不能代替生产部署或长程等价。源码提案。

V57：性能归因

单项加速在完整图中可能暴露通信。作者表中shared GEMM加入时慢0.014秒，最终移除却慢0.35%/0.22%；条件效果不能当组件独立收益。时间降幅、相对速度与MFU百分点需分开。性能图解。
