Loss 下降之前，先检查分母有没有变形

V136，2026-10-08。本章回答一个具体问题：改变数据配比后，loss 变小，是否一定意味着模型学得更好？如果权重归约的数值语义发生变化，答案可能是否定的。这里执行了固定版本的原始 Python 函数与 CPU CE 参考实现，完成 12 项控制；没有执行融合 GPU 内核，也没有证明 Hero 训练发生过下面的异常。

同一份权重，在两个地方用了不同精度

加权平均 CE 的定义是 L = sum(w_i * CE_i) / sum(w_i)。如果所有权重同时乘正数 c，精确算术下 loss 与参数梯度都应保持不变。这提供了一个无需训练大模型的检查办法。

固定源码中的共享 CE 接口先把权重转换为 token loss 的 dtype，再计算加权 loss；本次使用 FP32 loss。而外层 Grug 包装器请求逐 token loss 后，另行对原始权重求和作为分母。于是直接传入低精度权重时，分子用提升后的权重，分母仍按原权重 dtype 返回。分子精度足够，并不保证归一化正确。

这里说的是归约输出的可表示范围与舍入结果，不推断底层实现每一步加法都使用低精度。分布式归约还涉及设备分片、局部分母及 collective，本次未测。

实测：有限的零 loss 也可能是假象

控制模型只有一个隐藏特征、两个类别，分类头全零，标签全为类别 0。每个有效位置的 CE 都是 ln(2)，基准分类头梯度是 [-0.5, +0.5]。这不是训练轨迹，而是刻意排除模型和数据内容变化的微型对照。

入口与权重 有效权重的 FP32 和 外层实际分母 loss 分类头梯度
直接调用，257 个 BF16 单位权重 257 256 0.695855 [-0.501953, +0.501953]
直接调用，257 个 FP32 单位权重 257 257 0.693147 [-0.5, +0.5]
直接调用，65,536 个 FP16 单位权重 65,536 inf 0，且有限 [0, 0]
上一行的权重全部乘 0.5 32,768 32,768 0.693147 [-0.5, +0.5]
先把上述 FP16 权重提升到 FP32 65,536 65,536 0.693147 [-0.5, +0.5]
原始 causal 构造器，65,537 个 FP16 输入位置 65,536 65,536，FP32 0.693148 [-0.5, +0.5]

BF16 对照的误差因子约为 257/256，即 0.390625%。FP16 对照更隐蔽：分母变成 inf，有限分子除以 inf 得到零，梯度也归零。isfinite(loss) 会通过，所以“没有 NaN”不足以判定该步骤正常。同乘 0.5 改变了实际 loss 与梯度，违反了应有的缩放不变性。

最后一行尤其重要：原始 GrugLmExample.causal 会将给定权重与 FP32 取共同 dtype，再施加 causal mask。它把最后一个目标屏蔽，并在进入包装器前输出 FP32 权重。这个正常入口在本次选定控制中避开了问题。不能把绕过构造器的反例写成 Hero 已发生的事故。

对数据配比研究意味着什么

采样权重决定抽到哪些样本，loss 权重决定抽到之后如何进入目标函数，两者不能混为同一个参数。数学数据占比从 5% 改到 10%，通常首先改变样本频率；它是否同时改变 token 权重，需要查看实际输入张量。

如果两个实验改变了有效 token 数、packing、mask 或样本构造入口，必须先确认它们的分母语义一致，再讨论领域迁移。上述反例说明归约错误可以伪装成 loss 改善，但不能据此解释既有 Marin 配比实验的优劣；我们没有那些运行的实际权重 dtype 和归约张量。

提升 dtype 也有边界：权重 2^-26 先转 FP16 会在本次 CPU 控制中变为零，再转 FP32 仍是零。因此保护应尽量在权重生成和保存之前建立，而非只在最终求和时补一次转换。对于本来已能准确表示的单位权重，提前提升有效。

可以复用的验收规则与排查顺序

  1. 在真实数据入口记录权重 dtype、有效目标数、FP32 权重和；同时记录包装器实际分母及 loss 分子，不能只看归一化后的标量。
  2. 用相同样本和参数，把所有正权重共同缩放为 0.5、1、2，在安全数值范围内比较 loss 与梯度，提前规定误差容限。不要缩放采样概率后重抽样，那会换掉测试对象。
  3. 测试真实构造器与直接调用两条路径，确认缓存读取、自定义数据集及恢复后的输入是否继承同一保护。源码有保护不等于每条运行路径都经过保护。
  4. 逐步核对单设备、跨设备与梯度累积。梯度累积还须区分每个 microbatch 的平均再平均，与总分子除以总权重；dtype 正确不会自动修复这个语义差异。
  5. 出现异常时先冻结配比实验的效果归因，定位权重表示、分母溢出或归约方式，再决定是否需要重跑。同样，仅凭微型反例不能废弃原有实验。

本次不修改上游代码。将权重生成、分子与分母统一为足够精度，并对实际权重和检查有限性，是候选修正方向；完整实现还需测试分布式归约与融合内核，不把局部对照视为生产修复验收。

V137：局部分母有限，跨设备求和后仍可能溢出

V136 只执行无 mesh 分支。V137 启动一个独立 JAX 进程，配置四个本地虚拟 CPU 设备，实际执行原包装器中的 jax.shard_map、jax.lax.psum 及其自动微分。这次不是用 Python 相加模拟 collective，也不是四台机器或 GPU 测试。融合 CE 仍明确替换为原 CPU 参考实现；sharding 查询与重分片辅助函数使用小型适配器，其中重分片实际调用 device_put 和 NamedSharding。

最后一行与“只有一个空片”不同。一个空片并不会必然导致全局梯度异常：其他片仍有目标时，原实现先聚合总分子与总分母，再做除法，本次 FP32 对照通过。所有片都为空时，where 的零输出保护仍未让本次自动微分梯度变得有限。这延续了已有单设备的零分母结论，但增加了原 collective 路径的证据。

复制轴控制也不等于执行了词表分片：原包装器把 lm_head 设为复制，本次 model 轴上的副本不承载不同词表。它只验证本次 token sharding 声明下，分母没有沿无关复制轴额外累加；不能推广为所有模型并行设计都已正确。

对大批量训练的具体影响

如果全局参与求和的权重和超出了归约输出 dtype 的范围，多加数据并行设备并不能靠缩小单片分母解决问题。本例的 65,536 个目标拆成四份，每份都没有溢出，全局 FP16 分母依然溢出。检查必须覆盖 局部权重和 → 全局权重和 → 梯度累积总权重，且分别注明 dtype、参与轴与是否包含复制副本。

这不意味着 Hero 的大批量必然失效。V136 已验证正常 causal 构造入口输出 FP32，本轮则验证了 FP32 在选定四设备控制中的正确结果。实际生产入口、真实权重 dtype、GPU 编译和多主机通信仍缺运行证据。

对于配比实验，新增一个可执行门槛：固定全局样本集合与权重，对照单设备和设备分片后的 loss/梯度；至少覆盖不均目标数、空片、两个 token 轴及复制轴。分片只是实现策略时，不应改变希望优化的目标。若同时改变样本、精度或累积方式，应逐项拆开，不能把差异全部归因于数据配比。
